## 1. Audit Purpose and Scope

Following the merge of Release PR #2 (`release: prepare FlexNoC v0.2.0`) into `main` at commit `e87277a`, an independent engineering audit was conducted to reconcile all public and engineering documentation against the authoritative, cycle-accurate simulation datasets and RTL testbench sources.

The scope of this audit encompasses:
1. Reconciling benchmark sweep data between raw simulation output (`results/experiments_summary.csv`, `results/experiments_summary.json`) and published markdown tables.
2. Correcting historical typos in workload configuration parameters (injection count, hotspot destination node ID).
3. Aligning verification reporting language with standard hardware verification semantics (distinguishing dynamically evaluated assertions from code/functional coverage).
4. Qualifying architectural liveness and deadlock-freedom claims to reflect empirical observation under standard endpoint consumption assumptions.
5. Clarifying generic logic synthesis cell counts from target-specific physical ASIC/FPGA PPA metrics.
6. Ensuring strict cross-document consistency across `README.md`, `FLEXNOC_V0.2.0_RELEASE_NOTES.md`, and `verification-results.md`.

## 4. Benchmark Reconciliation & Methodology Analysis

### 4.1 Root Cause of the Benchmark Discrepancy
In the initial draft of `FLEXNOC_V0.2.0_RELEASE_NOTES.md` and `README.md`, an abbreviated subset of the 24 points was manually transcribed into markdown for brevity:
- Release notes displayed 5 Uniform Random points, 4 Hotspot points, and 4 Neighbor points (13 rows total).
- README displayed 4 Uniform Random points, 3 Hotspot points, and 3 Neighbor points (10 rows total).
- However, the explanatory text correctly cited 24 empirical load points, and `docs/performance-methodology.md` contained all 24 points across 3 separate tables.
- **Resolution**: Both documents now feature the complete, unified **24-row empirical table**, eliminating any visual discrepancy or ambiguity.

### 4.2 Benchmark Execution Contract
- **Offered Rate**: Bernoulli trial probability evaluated each clock cycle per node where `in_local_ready == 1`.
- **Packet Injected Count**: `packets = 350` passed via `+PACKETS=350` to the simulation harness. All 24 points injected exactly 350 flits.
- **Packet Delivered Count**: Exactly 350 flits delivered across all 24 points (100.00% delivery, 0.00% loss).
- **Aggregate Throughput**: Total flits delivered across the entire 16-node network divided by total elapsed clock cycles from start of injection through drain:
  $$\Theta = \frac{N_{\text{delivered}}}{T_{\text{total\_sim\_cycles}}} \quad (\text{flits/cycle})$$
- **Latency Accounting**: Cycle-accurate difference $L_i = T_{\text{eject}} - T_{\text{inject}}$ where injection cycle is stamped into the 16-bit flit payload upon source handshake (`in_local_valid && in_local_ready`) and extracted upon destination handshake (`out_local_valid && out_local_ready`).
- **Warm-Up and Drain**: 10 clock cycles of reset warm-up. Following injection cessation, a bounded drain period of up to 2,000 cycles executes until `total_delivered == total_injected`. If packets remain un-drained at timeout, the testbench exits with code `1`. All 24 points drained cleanly within 55 to 470 simulation cycles.

### 4.3 Hotspot Destination Selection and Self-Destination Semantics
In `tb/traffic/tb_mesh_performance.sv`, the destination selection function for Hotspot Contention executes:
```systemverilog
if ($urandom_range(0, 99) < 30) begin
    dst = 0;
end else begin
    do begin
        dst = $urandom_range(0, NUM_NODES-1);
    end while (dst == src);
end
```
- **Hotspot Branch (30%)**: Selects Node 0 as destination unconditionally. When $src = 0$, this selects local loopback ($dst = src = 0$), which the router architecture naturally handles and is reflected in the 2-cycle minimum latency.
- **Uniform Branch (70%)**: Excludes the source node via the `while (dst == src)` loop constraint.
- **Terminology Precision**: The phrase "30% of traffic directed to Node 0" defines the destination-selection rule in generation trials. Raw benchmark datasets record aggregate metrics and do not tabulate per-hop or source-destination breakdown, so no post-hoc self-destination count is inferred.

## 8. Remaining Limitations

The v0.2.0 release scope remains explicitly bounded as follows:
1. **Single-Flit Scope**: Architecture natively processes fixed-width 32-bit single-flit packets. Multi-flit packet mechanics (head/body/tail framing, atomic reservation locking, 5-bit counters) are specified in `docs/architecture/` for Milestone v0.3.0 and are not present in v0.2.0 RTL.
2. **Single Physical Channel**: No virtual channel multiplexing; links carry one flit buffer at a time.
3. **Oblivious Routing**: Dimension-order XY routing is purely deterministic; dynamic adaptive routing is out of scope.
4. **Single Clock Domain**: All mesh routers operate synchronously on a single clock domain.
5. **Physical Synthesis**: Cell counts reflect generic gate-level elaboration; ASIC standard-cell place-and-route and FPGA bitstream generation require target-specific toolchains.
